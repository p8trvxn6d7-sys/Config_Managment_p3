# Ассемблер и интерпретатор УВМ (вариант 31)

Практическая работа № 3 по дисциплине «Конфигурационное управление»
(ИКБО-41-25, РТУ МИРЭА). Язык реализации — Python 3.9+, сторонние
библиотеки не нужны.

## 1. Общее описание

Проект — ассемблер и интерпретатор для учебной виртуальной машины (УВМ).

- **Ассемблер** читает текст программы на «алгебраическом» языке, переводит
  его во внутреннее представление (список команд с полями `A`, `B`, `C`),
  затем в машинный код и записывает результат в двоичный файл.
- **Интерпретатор** читает двоичный файл, разбирает команды, выполняет их
  над моделью УВМ (регистры и память) и сохраняет дамп памяти в XML.

Статус этапов:

| Этап | Содержание | Статус |
|------|------------|--------|
| 1 | Перевод программы в промежуточное представление | выполнен |
| 2 | Формирование машинного кода | выполнен |
| 3 | Интерпретатор и операции с памятью | выполнен |
| 4 | АЛУ (команда `abs()`) | — |
| 5 | Тестовая задача | — |

## 2. Описание языка и настроек

### 2.1. Команды УВМ

Все команды начинаются с поля `A` (биты 0–7) — кода операции.
Номер регистра — 6 бит (0–63), константа и адрес — 31 бит
(0 … 2 147 483 647).

| Команда | Запись на ассемблере | A | B | C | Размер |
|---------|----------------------|---|---|---|--------|
| Загрузка константы | `rB = C` | 140 | биты 8–13, регистр | биты 14–44, константа | 6 байт |
| Чтение из памяти | `rB = mem[C]` | 21 | биты 8–13, регистр | биты 14–44, адрес | 6 байт |
| Запись в память | `mem[C] = rB` | 171 | биты 8–13, регистр | биты 14–44, адрес | 6 байт |
| Унарная операция `abs()` | `mem[rC] = abs(rB)` | 146 | биты 8–13, регистр | биты 14–19, регистр | 3 байта |

Семантика:

- `rB = C` — записать константу `C` в регистр `B`;
- `rB = mem[C]` — записать в регистр `B` значение из памяти по адресу `C`;
- `mem[C] = rB` — записать значение регистра `B` в память по адресу `C`;
- `mem[rC] = abs(rB)` — вычислить модуль значения регистра `B` и записать
  в память по адресу, который лежит в регистре `C`.

Интерпретатор выполняет `LOAD`, `READ` и `WRITE`. Команда `abs()`
разбирается декодером, но её выполнение будет добавлено на этапе 4: пока
интерпретатор сообщает, что команда не поддерживается.

### 2.2. Синтаксис ассемблера

- Одна команда на строку.
- Регистры: `r0` … `r63`.
- Числа: десятичные (`374`), шестнадцатеричные (`0x176`), двоичные
  (`0b101110110`). Отрицательные числа не поддерживаются.
- Комментарий начинается с `#` и идёт до конца строки.
- Пустые строки игнорируются; регистр букв и пробелы вокруг `=`, `[`, `]`,
  `(`, `)` значения не имеют.

Пример (`examples/spec_tests.asm`) — команды из тестов спецификации:

```
# Тестовые команды из спецификации УВМ (вариант 31)
r54 = 374            # LOAD:  A=140, B=54, C=374
r9 = mem[514]        # READ:  A=21,  B=9,  C=514
mem[737] = r54       # WRITE: A=171, B=54, C=737
mem[r54] = abs(r9)   # ABS:   A=146, B=9,  C=54
```

### 2.3. Машинный код

Поля команды собираются в одно целое число: поле занимает биты от
первого до последнего (нумерация с нуля, от младшего бита). Число
записывается в байты от младшего к старшему (little-endian), длина записи
равна размеру команды. Команды в файле идут подряд, без выравнивания и
заголовка.

Пример для `r54 = 374` (`A=140, B=54, C=374`):

```
140 | (54 << 8) | (374 << 14) = 0x5DB68C
байты: 0x8C, 0xB6, 0x5D, 0x00, 0x00, 0x00
```

### 2.4. Аргументы командной строки ассемблера

```
python -m uvm <source> <output> [--test]
```

| Аргумент | Назначение |
|----------|------------|
| `source` | путь к исходному файлу с текстом программы |
| `output` | путь к двоичному файлу-результату |
| `-t`, `--test` | режим тестирования: вывести байты каждой команды |

После ассемблирования выводится число команд: `Ассемблировано команд: N`.
В режиме тестирования перед ним по одной строке на команду выводятся байты
в формате тестов спецификации (`0x8C, 0xB6, ...`).

### 2.5. Модель УВМ (интерпретатор)

- **Память команд** — байтовая последовательность программы, загруженная из
  двоичного файла. Доступна только для чтения. Счётчик команд — смещение
  в байтах.
- **Память данных** — массив из 65 536 ячеек (адреса 0–65535), изначально
  заполненных нулями. Ячейка хранит целое число; разрядность в
  спецификации не задана. Память команд и память данных разделены.
- **Регистры** — 64 регистра (`r0` … `r63`), изначально нулевые.

Цикл интерпретации: прочитать команду по счётчику команд → разобрать её во
внутреннее представление (декодер) → выполнить → сдвинуть счётчик на размер
команды. Работа заканчивается, когда программа кончилась.

Ошибки выполнения (неизвестный код операции, обрезанная команда, адрес за
пределами памяти данных, неподдерживаемая команда) сообщаются в `stderr`
со смещением команды, код завершения — 1:

```
Ошибка: смещение 6: адрес 65536 вне памяти данных (размер 65536)
```

### 2.6. Аргументы командной строки интерпретатора

```
python -m uvm.interpreter <program> <dump> <FIRST:LAST>
```

| Аргумент | Назначение |
|----------|------------|
| `program` | путь к бинарному файлу с ассемблированной программой |
| `dump` | путь к XML-файлу, куда сохраняется дамп памяти данных |
| `FIRST:LAST` | диапазон адресов дампа, границы включены (например, `10:24`) |

После выполнения выводится число выполненных команд: `Выполнено команд: N`.

### 2.7. Формат дампа памяти

Дамп — XML-файл: корневой элемент `memory` с атрибутами `first` и `last`,
внутри по элементу `cell` на каждый адрес диапазона.

```xml
<?xml version='1.0' encoding='utf-8'?>
<memory first="10" last="12">
  <cell address="10" value="7" />
  <cell address="11" value="42" />
  <cell address="12" value="13" />
</memory>
```

## 3. Сборка и тесты

Сборка не требуется. Нужны Python 3.9+ и `make` (необязательно).

```
make test    # запустить тесты (unittest)
make run     # ассемблировать examples/spec_tests.asm в build/spec_tests.bin
make demo    # скопировать массив: ассемблер -> интерпретатор -> XML-дамп
make clean   # удалить build/ и __pycache__
```

Без `make`:

```
python3 -m unittest discover -s tests -t . -v
PYTHONPATH=src python3 -m uvm examples/spec_tests.asm out.bin --test
PYTHONPATH=src python3 -m uvm examples/copy_array.asm out.bin
PYTHONPATH=src python3 -m uvm.interpreter out.bin dump.xml 10:24
```

Тесты в `tests/`:

- `test_spec_examples.py` — поля и значения команд совпадают с тестами
  спецификации (`A=140, B=54, C=374` и т. д.);
- `test_encoder.py` — байтовые последовательности из спецификации, размеры
  команд, граничные значения, программа из `examples/spec_tests.asm`;
- `test_decoder.py` — разбор байтов из спецификации в поля, взаимная
  обратность кодирования и декодирования, ошибки;
- `test_machine.py` — команды `LOAD`, `READ`, `WRITE`, раздельная память,
  счётчик команд, ошибки выполнения;
- `test_dump.py` — структура XML-дампа, проверка диапазона, запись файла;
- `test_interpreter.py` — командная строка интерпретатора и тестовая
  программа копирования массива;
- `test_translator.py` — синтаксис, комментарии, системы счисления, границы
  полей, ошибки, согласованность таблицы синтаксиса со спецификацией;
- `test_cli.py` — режим `--test`, запись двоичного файла, ошибки ассемблера.

## 4. Примеры использования

### 4.1. Тесты из спецификации (ассемблер)

```
$ make run
0x8C, 0xB6, 0x5D, 0x00, 0x00, 0x00
0x15, 0x89, 0x80, 0x00, 0x00, 0x00
0xAB, 0x76, 0xB8, 0x00, 0x00, 0x00
0x92, 0x89, 0x0D
Ассемблировано команд: 4
```

### 4.2. Копирование массива (интерпретатор)

Программа `examples/copy_array.asm` записывает массив из пяти элементов
`7, 42, 13, 5, 99` по адресам 10–14, затем копирует его по адресам 20–24:

```
$ make demo
Ассемблировано команд: 20
Выполнено команд: 20
<?xml version='1.0' encoding='utf-8'?>
<memory first="10" last="24">
  <cell address="10" value="7" />
  <cell address="11" value="42" />
  <cell address="12" value="13" />
  <cell address="13" value="5" />
  <cell address="14" value="99" />
  <cell address="15" value="0" />
  ...
  <cell address="20" value="7" />
  <cell address="21" value="42" />
  <cell address="22" value="13" />
  <cell address="23" value="5" />
  <cell address="24" value="99" />
</memory>
```

Ячейки 20–24 содержат ту же последовательность, что и 10–14, значит
копирование работает корректно. Это же проверяет тест
`tests/test_interpreter.py`.

## 6. Коммиты

Сообщения коммитов оформляются по спецификации Conventional Commits в виде
`тип(stageN): описание`, например `feat(stage3): ...`. Подробности этапа
перечисляются в теле коммита.
